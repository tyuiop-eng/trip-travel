# Тестовый план — команда 2, спринт 09–14.11.2026

## 1. Цель и охват
Проверить соответствие программы обязательным требованиям ТЗ (пункты 1–8): корректное поведение
на позитивных сценариях и явный отказ без порчи данных на ошибочных вводах и файлах.

## 2. Уровни проверок
- **Модульные** — каждый участник пишет на свой модуль (pytest), проверяются до PR.
- **Сквозные** — QA, через меню по пользовательским сценариям.
- **Регресс** — повторный прогон сквозных сценариев после изменений четверга.

## 3. Сквозные сценарии

### E2E-1. Жизненный цикл поездки
Шаги: создать поездку → добавить расходы по всем четырём категориям → открыть отчёт →
выйти → запустить программу заново → открыть отчёт снова.
Ожидается: длительность в календарных днях включительно; расходы по категориям;
остаток = бюджет − расходы; после перезапуска поездка и расходы на месте.

### E2E-2. Отказы не портят данные
Шаги: поочерёдно вводить — пустое название; бюджет 0, −500, «abc»; дату 2026-02-30;
окончание раньше начала; расход к несуществующей поездке; категорию «еда»; сумму 0.
Ожидается: после каждого отказа — сообщение с причиной; запись не создана и не изменена;
список поездок и расходов до и после совпадает.

### E2E-3. Импорт расходов из CSV
Варианты:
а) корректный файл (`data/expenses_example.csv`) — все строки добавлены, отчёт показывает число;
б) файл с одной плохой строкой (`data/expenses_bad.csv`) — отклонён целиком;
в) файл с неверными заголовками — отказ файла с указанием причины;
г) дубликат номера внутри файла и среди сохранённых — отклонение;
д) расход к несуществующей поездке — отклонение.
Ожидается: частичных добавлений нет ни в одном варианте.

### E2E-4. Фильтр и выгрузка XLSX
Шаги: задать фильтр «поездка + категория» → сверить экран с ожидаемым списком →
выгрузить XLSX → открыть файл.
Ожидается: порядок строк на экране и в файле совпадает; итоги листа «Итоги» равны суммам
выбранных строк; пустая выборка даёт заголовки и нулевые итоги; исходные CSV не изменились.

## 4. Модульные проверки по зонам
- Хранение поездок (Лапатинский): уникальность номеров; отказ на пустых полях;
  сортировка списка — дата начала, затем номер.
- Расходы и бюджет (Ларин): допустимые категории и суммы; превышение бюджета сохраняет
  расход и даёт отрицательный остаток; отсутствие расходов — нулевая сумма.
- Даты, отчёты, импорт (Радыгин): существование дат в календаре; длительность включительно;
  отчёт об ошибках импорта с номерами строк; выгрузка XLSX (порядок, числовые суммы, пустая выборка).

## 5. Шаблон дефекта (Issue)
Заголовок · пункт ТЗ · шаги воспроизведения · ожидаемый результат · фактический результат ·
коммит (`git rev-parse HEAD`) и среда запуска.
